# Bundler-Compatible WASM Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `stabileo-engine@0.1.1` with a bundler-resolvable WASM fallback and upgrade FastPallet to the verified release.

**Architecture:** Normalize wasm-bindgen's generated fallback filename at the SDK build boundary, then verify the built and packed JavaScript references only shipped sibling assets. Release from `main` through the existing OIDC GitHub Actions workflow and consume the exact published artifact in FastPallet.

**Tech Stack:** TypeScript, Node.js, shell, wasm-pack, tsdown, Vitest, Playwright, npm trusted publishing, GitHub Actions, Next.js Turbopack.

## Global Constraints

- Preserve the single branded `dist/stabileo-engine.wasm` asset.
- Preserve explicit `initStabileoEngine({ wasm })` behavior.
- Fail the build unless exactly one wasm-bindgen fallback is normalized.
- Publish only through the existing GitHub Actions OIDC workflow.
- Prove FastPallet with a real browser flow, not unit tests alone.
